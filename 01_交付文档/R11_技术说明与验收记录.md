# R11 技术说明与验收记录

本目录是独立增强工作副本。R10 已交付包保持不变。**R11 尚未全面达标，不能以全部通过送审。** 文件夹名表示攻坚目标，不能作为通过证明。旧 R8—R10 文档与结果均是历史材料。

## 本次实现

1. **真实模型与执行合同分离。** `model_controlled_executor.py` 让实际本地模型提出工具调用；`execution_contract.py` 将服务器、工具名、参数的规范 JSON 哈希、顺序及返回绑定与接触外部内容之前确定的批准计划逐项比较。模型不能扩权、增加步骤或修改收件人。拒绝后可以继续执行批准计划中未完成的步骤；未知结果的已发起调用不能自动重试，防止重复支付等副作用。这适用于预定义有限业务流程，并不自动覆盖任意自然语言任务。
2. **输入及策略边界。** JSON 深度、节点数、字符串和整数长度均有限；浮点值必须有限，策略版本不接受布尔值。部署时验证计划和输入约束，不将外部内容转换成可执行代码。
3. **快速学习筛选。** SparseInjectionModel 对词、双词和词内字符三元组做有界线性评分，参数文件为可审计 JSON。按任务组划分训练/校准，并剔除跨组冲突。该筛选器独立使用的正常任务拒绝率超标，**不能独立用于生产阻断**。
4. **结合任务的本地复核。** ContextualIntent 将原始用户任务、实际控制参数、工具说明和带来源的前序返回交给固定本地 Qwen3-4B。返回中的指令没有用户权限；模型允许也不能覆盖身份、对象授权、数据流及批准计划。输出仅接受严格布尔 JSON。超时、格式错误、证据超长均显式记录；风险操作拒绝，但这类拒绝是可用性损失，不能算有效攻击检出。
5. **保留已有图谱及数据流。** 资产关系图、运行时因果链、跨会话业务数据标签和解释记录继续独立执行。新模型复核是补充判断，不替代这些确定性约束。
6. **连接与审计。** 对部署指定的 MCP/模型地址复用标准连接池，保持调用者原有认证、Cookie、TLS 和代理语义；自定义适配器不被替换。基线与防护阶段使用相同连接机制。日志序列化失败现在计入 dropped 指标。

## 输入输出与复现

依赖和原有启动方式见历史 R10 说明；本机 Python 3.13。当前默认入口仍保留已测 R10 语义模型，增强判断路径须显式启用。

```powershell
$env:PYTHONUTF8='1'
$env:PYTHONIOENCODING='utf-8'
py -3.13 '08_实验脚本/run_r11_tests.py'
# 先检查官方本地模型文件 SHA；只管理本项目模型容器。
py -3.13 '08_实验脚本/deploy_local_verifier.py'
# 实验性级联，尚非达标生产配置。
py -3.13 '05_复现脚本/deploy_r3.py' --official-target --r11-sparse --intent-url http://agentrange-r11-verifier:8080 --evidence-name R11_local_review
```

`/agentguard/execute-model` 只有部署设置 `--model-url` 时启用，需要官方应用实际接受的身份；输入是批准的 plan_id、inputs 和有界 prompt。计划及对象授权由部署策略决定。输出包含结果、模型真实提议、执行/拒绝记录和恢复标志。正常 `/agentguard/execute` 仍为固定计划入口。

完整模型请求、返回和实际模拟工具调用见 `07_修复验证/real_model_4b_development`。所有外部攻击内容只是数据，不在宿主机执行、不发送真实外部邮件。CPU、外部归档和模型文件均保存来源、配置、哈希和原始失败结果。模型权重不应无说明地混入主交付压缩包；如拆分交付，必须同时提供固定来源、SHA 和下载/离线放置步骤。

## 模型服务稳定性

模型来源为 [Qwen 官方 Qwen3-4B-GGUF](https://huggingface.co/Qwen/Qwen3-4B-GGUF)，固定 revision `bc640142c66e1fdd12af0bd68f40445458f3869b`；Q4_K_M 文件 SHA 在部署脚本中校验。推理镜像固定 digest；本机 CUDA 12.8 镜像可用，CUDA 13 新镜像因驱动版本要求失败，未绕过检查或更改宿主机驱动。

首版服务两次被 cgroup OOM 终止。通过实际 `llama-server --help` 发现默认 RAM cache 8 GiB 大于容器限制；现设 128 MiB、关闭额外上下文检查点，并禁用 CUDA 图以限制额外缓存。限制为 2 CPU、6 GiB 内存、2 并发槽，宿主机端口仅绑定 localhost，文件系统只读。该变更仍需长时间和负载验证；不能因单次恢复就宣称稳定性达标。

## 全面验收门槛

必须同时有：静态资产精度及漏报、风险精度及漏报；框架利用和 Agent 行为各自的检出及误报；实际决策延迟小于 1 秒；完整防护和辅助服务 CPU 小于 5%；正常任务完成及无中断；真实原生函数帧、提示词、调用链和可解释决策；可从新解压目录运行的源码与技术/检测报告。任一指标缺证据或不通过，总状态就是未全面达标。原有官方静态/动态成功不能推导为所有外部任务成功。

## 最新优化与证据保存

`source_contract.py` 只对部署者持有的处理器源码做保守 AST 证明，记录文件 SHA、处理器及精确原始类型输入约束。没有函数调用、属性访问、外部读写、可变全局状态等行为的有限纯处理器，才允许省去执行意图的模型复核。工具自行宣称安全无效；该证明不覆盖整个进程、依赖或运行时内存篡改，也不豁免数据泄漏和对象授权。官方沙箱的 run_test 实际返回固定测试结果，并不执行传入命令；因此完整官方负载中 1,256 个调用被此证明卸除冗余复核，模型请求为零。这不能证明需要频繁模型判断的外部业务负载 CPU 达标。

`json_codec.py` 在固定 msgspec 0.21.1 可用时加速 JSON 读取，否则保留标准库路径。保留任意精度整数、编码、重复键和历史解析行为；写出的请求和策略规范哈希没有变化。微测试的解析 CPU 提速 1.656 倍只针对捕获消息解析，完整系统性能必须另测。新原生/网关镜像使用独立 R11 标签，旧 R10 镜像不覆盖。

外部 Gemini 的协议、选择清单、下载 Git blob SHA 和文件 SHA 已冻结，并保留当时 33 个源码文件。后续调优必须标注开发实验。运行 `08_实验脚本/verify_r11_protocol.py --source-snapshot` 校验原冻结实现；直接校验当前工作树如失败，表示源码已变化，不能把新实现冒充当时的独立结果。独立档案含不同模型，但任务、攻击族和数据域与已使用资料存在重合，不能宣称独立任务族泛化。
