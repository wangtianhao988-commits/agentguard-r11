# R11 未达标问题与证据

本清单以实测为准。新增能力和局部通过不代表全部比赛要求已达到。

| 问题 | 已确认根因或边界 | 后续验收条件 |
|---|---|---|
| 完整资源占用余量不足 | 纯处理器证明已卸除冗余模型判断；旧三轮仍有 5.0046%，新解析器首轮 5.0216% | 新冻结实现完整三轮均 <5%，含全部模型/辅助服务，不挑轮次 |
| 外部广泛检出不足 | 可观察注入漏掉 240 条，workspace 占 207；筛选和复核链未覆盖全部攻击表现 | 开发数据用于定位/训练；使用新的未见测试覆盖不同任务、工具和攻击族，达到检出 ≥95% |
| 正常任务拒绝超标 | Gemini 原标签下 10/132；7 条任务复核拒绝、2 条超时、1 条对象冲突 | 正常完成率与误报 <5% 同时验证；不要删除原模型选错参数的难例 |
| 真实任务范围有限 | 执行合同保障预定义有限流程，不自动解析任意自然语言授权 | 更多真实模型、实际 MCP 和未见业务的在线配对实验，记录实际效果与恢复 |
| 辅助模型繁忙时成本缺口 | 官方纯处理器负载产生零模型请求；非空标签微测试仅统计宿主进程 CPU | 模型复核频繁、非空持久标签并发业务的全链路成本/延迟测试 |
| 长时间零中断没有全面证据 | 模型已有 1,081 条档案测试未再次 OOM，但不等于长期可用性 | 长时间运行、并发、超时、重启、日志故障和持久化恢复检查 |

失败定位可运行 `08_实验脚本/analyze_external_r11.py`，输出原始路径、任务、实际调用与拒绝依据。该分析发生在独立冻结评估之后；这些样例今后必须算开发数据。不能把历史成功子集 130/134 的点估计 97.01% 写成总体外部泛化 95%。
